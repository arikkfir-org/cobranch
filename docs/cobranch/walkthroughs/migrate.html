migrate: the schema moves first

A Job per upgrade that brings the database to the build's schema, then exits. Pods never migrate; they wait. The rules it follows are what let pull requests merge in any order and upgrades roll without downtime.

An upgrade

Servers start at once and turn ready only when the schema is whole

  • Readiness is the gate. Every server's /readyz runs Schema.Check: an error until the database has every migration this build has. Old pods keep serving until new ones pass.
  • An advisory lock serializes migrators. Of several running at once, one migrates and the rest find nothing left. Each migration runs in its own transaction.
  • It waits for the database. MigrateUntilDone retries while the database is unreachable or starting, from a second up to a minute apart, and returns at once on a failure the next try would repeat.
Rules

Three rules every migration follows

1 · Numbers may land out of order. Goose normally refuses a migration numbered below one already applied. Cobranch applies those too, because pull requests built side by side merge in any order. So a migration never relies on a lower-numbered one that might merge after it, and "has a higher version" is never proof the schema is complete.

2 · Each release stays compatible with the one before. Both run side by side during a rolling upgrade. A column is dropped only once neither the new release nor the previous one reads it, so a rollback goes back one release at most.

3 · Long backfills do not run here. They run later, as work of the controller's.

Numbers are claimed up front, since two files with one number would fail the Job while GitHub shows no conflict.

Worth a closer look

Sixty-three files for a product not yet released widely

Before the first installation that must be upgraded in place, the history could be squashed into a handful of files per area. After that it cannot.

The chart names Argo CD

templates/migrate.yaml carries an argocd.argoproj.io/sync-wave annotation and a comment about Argo CD. Cobranch is meant to assume no delivery tool; an operator-set annotations value would say the same without the name.

Role permissions live in migrations

Each slice appends to built-in roles by fixed UUID in SQL, while auth/permissions.go holds the catalog and tests hold the two together. One source that generates the other would remove the cross-check.
