The path of a write

From a service call to an audited row

  • SQL is never written in Go. A store method calls a generated query and converts its row to the domain's type. The one exception reads goose's version table.
  • A store reaches the database through a scope. db.In(org) and db.Of(table, id) pin one organization, db.Deferred() waits for the work it joins to pin one, and db.Everywhere(why) spans organizations and says why. A read through a scope travels with its pin as one batch.
  • Scope.Transact(ctx, what, actor, fn) is the wrapper for writes. It begins a transaction pinned as its scope says, sets the actor, runs fn, and turns a unique violation into a ConflictError naming the constraint, which the store maps to "already there".
  • It is re-entrant. The transaction rides the context, so a store method called inside another's transaction joins it as a savepoint instead of opening a second connection. The outer actor stands, and so does the outer organization: work in another is refused.
  • sqlc's settings matter: at most 3 positional parameters before it generates a params struct, nullable columns become pointers, and uuid and timestamptz map to uuid.UUID and time.Time.

Who did it

One session variable, set per transaction

Transact runs SELECT set_config('cobranch.principal_id', $1, true). The true makes it local to the transaction, which is what makes it safe on a pool that shares connections.

NULL means Cobranch itself: a migration, a seed, maintenance's sweep, a session's touch, the controller following a pod. Passing uuid.Nil as the actor leaves the variable unset.

A nested Transact does not rename the actor. The savepoint acts for whoever the outer transaction named.

Not audited on purpose: transient rows (sign_in_flows) and history the controller writes (deliveries, job_runs), whose "who" is in events. Sessions audit only their making, revocation and deletion, not each use.

events is the domain's activity log, which pages show; audit_log is the row-level trail beneath it.

Review leads

Worth a closer look

The house rule asks for more than the scopes do

The house rules say every access runs in a transaction through one wrapper that sets the tenant, the user and the trace for row-level security. Every query now runs through a scope, which sets the organization; only Transact sets the principal, so a read names nobody, and nothing sets the trace.

Five copies of the same method

AuthStore, OrgStore, RepoStore, SecretStore and ArtifactStore each define an identical transact that forwards to the package's. An embedded base store would carry it once.

Four claim queries, one statement

The four SKIP LOCKED claims differ in table and returned columns. sqlc cannot template them, but their lease, defer and retry columns could at least share names and a documented shape.

Tenancy rests on the scope a store names

Row-level security holds a pinned query to its organization, so a query missing its org_id filter no longer leaks. Work under Everywhere is bound by nothing but its own filters: each such call names its reason, and those are the ones to review.
