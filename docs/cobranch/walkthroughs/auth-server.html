auth-server: who you are

The only workload that sends a browser to an identity provider and the only one that sets the session cookie. It serves no data. Every other workload resolves credentials through the same auth.Service, so this page also covers tokens and the authorizer.

Flow

A sign-in is four routes and one cookie

RouteDoes
GET /providersLists the identity providers, and the seeded demo users while seeding is on, for the sign-in page to draw
GET /sign-in?provider=&return= begins a flow at the provider; ?user= signs in as a seeded user. The return is a Console path or a Back-office URL, checked by SafeReturn
GET /callbackWhere the provider sends the browser back; completes the flow and sets the cookie
POST /sign-outRevokes the cookie's session, from the Console's or the Back-office's origin only
Credentials

Six kinds of token, one resolver

auth.Service.Authenticate switches on the token's prefix. Every server and the Git server call it through server.Authenticate; a live credential is marked used at most once a minute.

PrefixCredentialActs asHow the authorizer treats it
cbs_Session (the cookie)Its userEverything the user holds
cbp_Personal tokenIts userNarrowed to the permissions the token lists
cbk_API keyThe key, a principal of its organizationThe key's own grants
cbr_Run tokenThe run's jobWidened while the run runs: read the organization, do what the job declared
cba_Task tokenThe task's agentCapped by what the task's assigner holds
cbd_Delivery tokenThe delivery's targetWidened while the delivery renders

The one authorizer. Nothing is cached between requests, so a revoked grant fails the very next one. A service asks Can or Holds and never reads grants itself.

Things to know

Rules that live here

  • The cookie is scoped to the parent domain of every Cobranch URL (auth.CookieScope), so one sign-in reaches every API. With no URLs configured it falls back to a host cookie.
  • Cookie plus mutation needs JSON from the pages' origin. server.Authenticate refuses a cookie-authenticated POST, PUT, PATCH or DELETE that is not JSON or names another Origin. A bearer token is sent on purpose and skips the check.
  • Providers come from two places: the chart's values (read-only in the Back-office) and rows the Back-office adds, whose client secrets are sealed with the installation's secrets key.
  • Sign-up policy and self-serve organizations are settings: the chart's values lock them, otherwise the Back-office edits them.
  • Expiry is not here. maintenance deletes expired flows, sessions and task tokens hourly.
Review leads

Worth a closer look

Minting is spread, resolving is not

Resolution is one switch. Minting is in four places: auth (sessions, personal tokens, task tokens), and the Token methods of the runner, taskrunner and deliverer stores. Check they share the hash and hint code.

auth.Service is built four times

The API servers, the Auth server, the Git server and maintenance each construct their own auth.NewService(postgres.NewAuthStore(pool), nil, auth.Settings{}). Harmless, but a shared constructor in cmd/cobranch would say it once.
