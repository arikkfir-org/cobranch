Console: the product people see

Every page of Cobranch for its users: organizations, repositories, branches, issues, agents, artifacts. It is native ES modules and stylesheets with no build step and no framework, served by Caddy, calling the rest-server only.

First load

The shell names every file, and the browser asks for all of them at once

  • Caddy's templates writes two things into index.html: the configuration (where REST, Auth, Git and the Console answer, and the release) and the names of the files in each asset directory (listFiles).
  • Assets live under /assets/@<release>/. A Caddy serves only its own release's path. During a rollout a load that reaches the other release fails and reloads, up to three times, each under a path (~2, ~3) the browser never cached.
  • Every page module is imported up front, so a session runs one release throughout. Stylesheets link in a fixed order so the cascade is the same on every load.
  • start(loaded, root, again) is a contract across releases: an old shell may load a new console.js.

Things to know

Behaviours that cut across pages

  • Permissions shape the page. The Console reads the viewer's permissions and hides what they may not do; the API still decides.
  • Chats follow live by long-polling the REST API from a cursor (followChat in lib/chat.js), with a banner when it cannot.
  • Each page view is timed and its Git reads counted from Server-Timing, then posted in batches to /v1/page-views without the cookie. Nothing names who viewed what.
  • Theme is the person's, not the browser's. lib/theme.js keeps it in their preferences through the API and mirrors it in localStorage so the first paint is right.
  • Links marked data-nav route in the browser; anything else is a normal link.
Review leads

Worth a closer look

lib/ is two things

Fourteen small primitives share a flat directory with page-sized feature modules. Splitting them would make the layering above visible in the tree, and show which features import each other.

Reserved words in two languages

router.js lists the Console's own paths; orgs.ReservedSlugs and repos.ReservedSlugs list them in Go, held together by a test and a comment. The shell could receive them from the API.

api and apiPage

Two functions in lib/api.js repeat the fetch, the read count and the problem-to-error mapping. One could build on the other.

List pages look alike

Issues, runs, tasks, artifacts, commits and activity each draw a filtered, paged list. Check whether they share one list helper or each wires apiPage and "load more" again.
