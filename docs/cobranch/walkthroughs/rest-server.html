rest-server: the front door

The REST API under /v1/. The Console, scripts, job runs and agents all come through it, each as a principal of its own. It is the largest hand-written transport in the codebase.

Runs asDeployment, 2 replicas; reads pods/log in the job namespaces

Request path

From a request to a row, a Git object or a pod's log

The services are the same instances the graphql-server builds. Code reads leave through gitinternal with the viewer's own token, so the Git server checks who reads.

Surface

216 operations, by what they are about

Operations grouped by path. Everything below /orgs/{org} is scoped to one organization; /me is the viewer's own sessions, tokens, SSH keys, preferences and organizations.

Conventions

What every route does the same way

CachingEvery GET answers Cache-Control: private, no-cache; resources carry an ETag from their version, and changes need If-Matchrest/api.go, each area

Code map

A file per area, each a thin translation

A handler reads the generated request object, calls one service method with the viewer from the context, and maps the domain value to the generated response type. The files: orgs, repos, me, tokens, sshkeys, api_keys, code, files, diffs, viewed, runs, runlogs, environments, issues, labels, chats, issue_chats, conversations, agents, models, transcripts, spend, artifacts, secrets, activity, overview, usage, preferences, pageviews, report.

Three chat files

Hand-rolled ETag and cursor per area
