graphql-server: the same domain, as a graph

A second complete transport over the services the rest-server uses, with subscriptions over WebSocket. It is built and wired exactly like the REST API; only the adapter differs.

Subscriptions ride PostgreSQL's NOTIFY

The three subscriptions are chatUpdates, issueChatUpdates and conversationUpdates. Each server keeps one listening connection outside its pool (postgres.ListenChats); a lost connection wakes every watcher, since it may have missed some. The REST API's long poll uses the same hub.

Who needs both transports?

The Console uses REST alone, so GraphQL's 6.2k lines and 95 mutations serve API clients only. Either the two share their mapping layer, or one becomes the thin one.

Cursors, three ways

activity.go, chats.go and jobs.go each decode their own cursor, as their REST twins do.

Service interfaces declared twice

rest and graphql each declare Sessions, Organizations, Code and the rest. If they list the same methods, one set would do.
